0. Настройка и доступ
Откройте Git Bash в СВОЕЙ уже склонированной папке lab_GITBASH. Заново клонировать и выполнять git init здесь не нужно. Руслан проверяет в GitHub Settings → Collaborators, что Марат приглашён и принял приглашение. Не меняйте origin: адрес уже задан. Каждый выполняет локальные упражнения из отдельного файла. В общую историю не загружайте старые .git, bundles и каталоги work.

git --version
pwd
git remote -v
git status
git branch --show-current

====================================================================

1. Начальная страница
Настрой СВОЁ имя и настоящую почту либо GitHub noreply-адрес. Вместо ВАША_ПОЧТА укажи свой адрес. В корень lab_GITBASH скопируй только materials/index.html из архива. Проверь, что Git видит именно этот файл. Сначала создаём первый коммит, затем явно называем основную ветку master.

git config user.name "Дроздов Руслан Юрьевич"
git config user.email "ВАША_ПОЧТА"
git add index.html
git commit -m "Начальная страница совместного проекта"
git branch -M master
git push -u origin master
git status

====================================================================

3. Кнопка подписки
В index.html замени ТОЛЬКО <!-- subscribe --> на <button class="subscribe" type="button">Подписаться на новости</button>. Остальной файл не заменяй. После push попроси Марата посмотреть ветку в GitHub. Для этого этапа НЕ используйте кнопку Merge в GitHub: требуемый fast-forward выполни в Git Bash.

git checkout master
git pull --ff-only
git checkout -b feature/subscribe
# Здесь отредактировать index.html и сохранить
git diff
git add index.html
git commit -m "Добавлена кнопка подписки"
git push -u origin feature/subscribe
git checkout master
git merge --ff-only feature/subscribe
git push origin master

====================================================================

4. Общая точка перед параллельными задачами
Оба должны выполнить эти команды ПОСЛЕ отправки кнопки в master. Сравните полный хеш HEAD — он должен совпадать. Только после этого создавайте две ветки следующего этапа. Это гарантирует, что они начинаются от общего коммита.

git checkout master
git pull --ff-only
git rev-parse HEAD

====================================================================

5А. Цвет кнопки
В отдельной ветке замени в CSS ровно #2462b7 на #207447. Не меняй блок <!-- login -->. Отправь ветку; пока не сливай её с master до готовности ветки Марата.

git checkout -b feature/button-color
# Изменить цвет и сохранить index.html
git diff
git add index.html
git commit -m "Изменён цвет кнопки подписки"
git push -u origin feature/button-color

====================================================================

6. Объединение двух задач
Выполнять после push ОБЕИХ веток. Марат проверяет результат через GitHub. Первое слияние должно быть fast-forward; второе создаёт merge-коммит, поскольку ветки разошлись. Отдельные Pull Request можно использовать для обсуждения, но в этом сценарии НЕ нажимать Merge в GitHub до выполнения команд.

git checkout master
git pull --ff-only
git fetch origin
git merge --ff-only feature/button-color
git merge origin/feature/social-login -m "Объединены изменения участников"
git push origin master
git log --graph --oneline --all

====================================================================

7. Подготовка конфликта
После этапа 6 оба обновляют master и сравнивают HEAD. Пока оба не создали и не отправили конфликтные ветки, никто не сливает их в master. Ветки должны менять одну и ту же строку <h1>Учебное портфолио</h1>.

git checkout master
git pull --ff-only
git rev-parse HEAD

====================================================================

8А. Первая конфликтная ветка
Создай ветку и замени строку заголовка на <h1>Портфолио Руслана</h1>. Отправь ветку, затем дождись push Марата.

git checkout -b feature/heading-ruslan
# Изменить заголовок и сохранить
git add index.html
git commit -m "Вариант заголовка Руслана"
git push -u origin feature/heading-ruslan

====================================================================

9. Конфликт и его разрешение
После отправки обеих веток выполни слияния. Второе должно остановиться с CONFLICT и кодом 1: это ожидаемый учебный результат. Сохрани вывод status и файл с маркерами. В редакторе оставь ОДИН заголовок <h1>Учебное портфолио Руслана и Марата</h1>, убери <<<<<<<, =======, >>>>>>>. Только после правки выполняй add и commit. Если конфликт не возник, не придумывай его: проверь общую точку и реально изменённые строки.

git checkout master
git pull --ff-only
git fetch origin
git merge --ff-only feature/heading-ruslan
git merge origin/feature/heading-marat
git status
cat index.html
# Исправить конфликт и сохранить index.html
git add index.html
git commit -m "Разрешён конфликт заголовка"
git push origin master
git status
git log --graph --oneline --all

====================================================================

11. Метки
Рабочее дерево должно быть чистым. Убедись, что имена меток ещё не заняты. Создай временную легковесную метку, посмотри и удали её. Затем создай аннотированную 1.0 на итоговом сайте и 1.1 на предыдущем коммите (как упражнение методички, не семантический номер релиза). Отправь только эти две метки, не чужие.

git checkout master
git pull --ff-only
git status
git tag
git tag practice-light
git show practice-light --no-patch
git tag -d practice-light
git tag -a 1.0 -m "Совместная версия учебного сайта"
git tag 1.1 HEAD~1
git tag -l '1.*'
git show 1.0 --no-patch
git push origin 1.0 1.1

====================================================================

13. Подключение подмодуля
В основном lab_GITBASH подставь реальный URL библиотеки Марата. Ничего не меняй в каталоге app вручную. Добавь .gitmodules и gitlink в общий коммит. Для HTTPS GitHub не нужен protocol.file.allow.

git checkout master
git pull --ff-only
git submodule add URL_БИБЛИОТЕКИ app
cat .gitmodules
git status
git ls-files --stage app
git add .gitmodules app
git commit -m "Подключена библиотека Марата как подмодуль"
git push origin master

====================================================================

15. Материалы для отчёта
Оба сохраняют ВСЕ команды и вывод в свои журналы, не только скриншоты. Добавьте скриншоты дерева веток GitHub, обоих авторов в истории, меток, конфликта до исправления, чистого статуса после исправления и подмодуля. Заполните результаты в отчёте. Не публикуйте токены, пароли и закрытые данные. При ошибке push остановитесь и проверьте право записи; не используйте --force.

git status
git branch -a
git log --graph --oneline --all
git log --format="%h | %an | %s"
git remote -v
git submodule status
