ПЛАН ДЕЙСТВИЙ: МАРАТ
Общий репозиторий: https://github.com/RuslanGIT3/lab_GITBASH.git
Этапы выполнять в указанном порядке с паузами для второго участника.
Это инструкции, а не журнал уже выполненных команд.

0. Настройка и доступ
Откройте Git Bash в СВОЕЙ уже склонированной папке lab_GITBASH. Заново клонировать и выполнять git init здесь не нужно. Руслан проверяет в GitHub Settings → Collaborators, что Марат приглашён и принял приглашение. Не меняйте origin: адрес уже задан. Каждый выполняет локальные упражнения из отдельного файла. В общую историю не загружайте старые .git, bundles и каталоги work.

git --version
pwd
git remote -v
git status
git branch --show-current

====================================================================

2. Получение первого коммита
Выполнять ПОСЛЕ первого push Руслана. Настрой своё имя и свою почту. Команда --track ниже рассчитана на ваш пока пустой клон: нет собственных коммитов. Если уже работаешь в master с коммитами, вместо checkout --track выполни git checkout master и git pull --ff-only.

git config user.name "Дедин Марат Сергеевич"
git config user.email "ВАША_ПОЧТА"
git remote show origin
git fetch origin
ls
git checkout --track origin/master
ls
git status

====================================================================

4. Общая точка перед параллельными задачами
Оба должны выполнить эти команды ПОСЛЕ отправки кнопки в master. Сравните полный хеш HEAD — он должен совпадать. Только после этого создавайте две ветки следующего этапа. Это гарантирует, что они начинаются от общего коммита.

git checkout master
git pull --ff-only
git rev-parse HEAD

====================================================================

5Б. Демонстрационная форма входа
В своей отдельной ветке замени ровно <!-- login --> содержимым social-login-fragment.html. Цвет кнопки не меняй. Форма только демонстрационная: не вводите реальные пароли и не обещайте OAuth. Отправь ветку и сообщи Руслану.

git checkout -b feature/social-login
# Вставить блок формы и сохранить index.html
git diff
git add index.html
git commit -m "Добавлена демонстрационная форма входа"
git push -u origin feature/social-login

====================================================================

7. Подготовка конфликта
После этапа 6 оба обновляют master и сравнивают HEAD. Пока оба не создали и не отправили конфликтные ветки, никто не сливает их в master. Ветки должны менять одну и ту же строку <h1>Учебное портфолио</h1>.

git checkout master
git pull --ff-only
git rev-parse HEAD

====================================================================

8Б. Вторая конфликтная ветка
От того же состояния master создай свою ветку. Замени ту же строку на <h1>Портфолио Марата</h1> и отправь ветку. Не получай уже слитый вариант Руслана перед созданием своей ветки.

git checkout -b feature/heading-marat
# Изменить заголовок и сохранить
git add index.html
git commit -m "Вариант заголовка Марата"
git push -u origin feature/heading-marat

====================================================================

10. Проверка объединённого сайта
Получи итоговый коммит. Открой index.html браузером: общий заголовок, зелёная подписка и две кнопки входа должны быть видны. Проверь все три кнопки. Их действие — локальное сообщение, без реального входа и подписки.

git checkout master
git pull --ff-only
git status
git log -1 --format=fuller
git rev-list --parents -n 1 HEAD

====================================================================

12. Отдельный репозиторий подмодуля
В СВОЁМ GitHub создай новый пустой репозиторий lab_GITBASH_library без README. Это отдельный репозиторий, НЕ папка в основном. Открой новое окно Git Bash вне lab_GITBASH; подставь фактический URL вместо URL_БИБЛИОТЕКИ. Скопируй туда library.txt из материалов. Если имя автора не задано глобально, настрой его локально, как на этапе 2. Сообщи Руслану URL. Для приватного репозитория дай Руслану доступ.

git clone URL_БИБЛИОТЕКИ
cd lab_GITBASH_library
git config user.name "Дедин Марат Сергеевич"
git config user.email "ВАША_ПОЧТА"
# Скопировать library.txt в этот каталог
git add library.txt
git commit -m "Учебный файл библиотеки"
git branch -M master
git push -u origin master

====================================================================

14. Получение и проверка подмодуля
Вернись в ОСНОВНОЙ lab_GITBASH. После pull подмодуль нужно инициализировать и загрузить. В индексе app должен иметь режим 160000. Затем в отдельном новом окне/папке проверь чистое клонирование с подмодулями; папка lab_GITBASH-check до этого не должна существовать.

git checkout master
git pull --ff-only
git submodule init
git submodule update
git submodule status
cat app/library.txt
git fetch origin --tags
git tag -l '1.*'
# Далее из родительского каталога, вне текущего клона:
git clone --recurse-submodules https://github.com/RuslanGIT3/lab_GITBASH.git lab_GITBASH-check
cd lab_GITBASH-check
git submodule status
cat app/library.txt

====================================================================

15. Материалы для отчёта
Оба сохраняют ВСЕ команды и вывод в свои журналы, не только скриншоты. Добавьте скриншоты дерева веток GitHub, обоих авторов в истории, меток, конфликта до исправления, чистого статуса после исправления и подмодуля. Заполните результаты в отчёте. Не публикуйте токены, пароли и закрытые данные. При ошибке push остановитесь и проверьте право записи; не используйте --force.

git status
git branch -a
git log --graph --oneline --all
git log --format="%h | %an | %s"
git remote -v
git submodule status
